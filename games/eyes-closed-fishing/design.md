# 《눈 감고 낚시》 게임 기획서

| 항목 | 내용 |
| --- | --- |
| 장르 | 사운드 기반 캐주얼 낚시 · 원터치 |
| 플랫폼 | 모바일 (iOS / Android) |
| 플레이 시간 | 1마리당 20~40초, 세션 3~10분 |
| 권장 환경 | 이어폰 착용, 화면 미주시 |
| 문서 버전 | v0.1 (MVP 기획) |

## 1. 개요

### 1.1 한 줄 콘셉트

> **화면을 보지 않고, 소리만 듣고 낚시하는 게임.**

화면에는 아무것도 없습니다. 물고기도, 낚싯대도, 게이지도 없습니다. 플레이어는 물소리, 입질 소리, 낚싯줄의 장력 소리만 듣고 손가락 하나로 낚시합니다.

### 1.2 디자인 기둥 (Design Pillars)

1. **소리가 곧 인터페이스** — 모든 게임 정보는 소리로 전달된다. 소리를 정확히 듣는 능력이 곧 실력이다.
2. **한 손가락, 두 가지 조작** — 짧게 터치 / 길게 누르기·떼기. 설명 없이도 10초 안에 익힐 수 있어야 한다.
3. **어디서든, 눈 감고** — 누워서, 산책 중 잠시 멈춰서, 대중교통에서 이어폰만 끼고 즐길 수 있다.
4. **짧고 촘촘한 긴장** — 기다림은 짧게, 신호는 자주. 지루할 틈을 주지 않는다.

### 1.3 차별점

| 기존 낚시 게임 | 《눈 감고 낚시》 |
| --- | --- |
| 화려한 그래픽, 게이지 UI | 검은 화면, UI 없음 |
| 시각 반응 중심 | 청각 판단 중심 |
| 장비·상점·강화 성장 | 순수 실력 + 수집 기록 |
| 화면 주시 필수 | 화면 미주시 플레이 가능 |

부가 가치: 시각장애인 플레이어도 동등하게 즐길 수 있는 **접근성 게임**으로서의 포지셔닝이 가능합니다.

## 2. 타깃 플레이어

- **주 타깃**: 짧은 틈새 시간에 가볍게 즐길 거리를 찾는 20~40대 모바일 캐주얼 유저
- **부 타깃**: 리듬·반응 게임 유저, ASMR·자연음 선호층, 시각장애인 게이머
- **플레이 상황**: 잠들기 전, 출퇴근길, 휴식 시간, 눈의 피로를 피하고 싶을 때

## 3. 핵심 게임 루프

```
 ┌──────────┐   탭    ┌──────────┐  입질 발생  ┌──────────┐
 │ ① 캐스팅 │ ──────▶ │ ② 대기    │ ─────────▶ │ ③ 챔질    │
 └──────────┘         └──────────┘            └──────────┘
      ▲                    │ 헛챔질/시간초과        │ 성공
      │                    ▼                       ▼
 ┌──────────┐         ┌──────────┐  릴링 완료  ┌──────────┐
 │ ⑤ 결과   │ ◀────── │ 실패 처리 │ ◀───────── │ ④ 릴링    │
 └──────────┘  끊김    └──────────┘   or 포획   └──────────┘
```

| 단계 | 플레이어 행동 | 들리는 소리 | 소요 시간 |
| --- | --- | --- | --- |
| ① 캐스팅 | 화면 아무 곳 탭 | 휘익 → 퐁당 | 약 1.5초 |
| ② 대기 | 듣고 기다리기 | 잔잔한 물소리, 작은 물방울, 가짜 신호 | 4~12초 |
| ③ 챔질 | 결정적 입질에 탭 | `촤박!` | 판정창 약 1.2초 |
| ④ 릴링 | 누르기 / 떼기 반복 | `드르륵` ↔ `끼이익` | 10~25초 |
| ⑤ 결과 | 듣기 | 큰 물튀김 + 음성 안내 | 약 3초 |

결과 안내가 끝나면 다시 탭하여 즉시 캐스팅할 수 있습니다.

## 4. 상세 시스템

### 4.1 게임 상태 머신

| 상태 | 진입 조건 | 유효 입력 | 전이 |
| --- | --- | --- | --- |
| `IDLE` | 앱 시작, 결과 종료 | 탭 | → `CASTING` |
| `CASTING` | 탭 | 없음 (입력 무시) | 연출 종료 → `WAITING` |
| `WAITING` | 착수 완료 | 탭 | 진짜 입질 발생 → `BITE` / 조기 탭 → `FAIL_EARLY` |
| `BITE` | 결정적 입질 재생 | 탭 | 판정창 내 탭 → `REELING` / 시간 초과 → `FAIL_LATE` |
| `REELING` | 챔질 성공 | 누르기 / 떼기 | 거리 0 → `CAUGHT` / 장력 한계 → `FAIL_SNAP` / 느슨함 지속 → `FAIL_ESCAPE` |
| `CAUGHT` | 포획 | 탭(스킵) | 안내 종료 → `IDLE` |
| `FAIL_*` | 실패 | 탭(스킵) | 안내 종료 → `IDLE` |

### 4.2 조작 규격

| 입력 | 판정 기준 | 사용 상태 |
| --- | --- | --- |
| 짧은 탭 | 터치 시간 < 250ms | 캐스팅, 챔질, 결과 스킵 |
| 길게 누르기 | 터치 유지 ≥ 250ms | 릴 감기 |
| 손 떼기 | 터치 종료 | 장력 해제 |

- 화면 **전체**가 단일 입력 영역입니다. 위치는 의미가 없습니다.
- 주머니 속 오입력 방지를 위해 `IDLE`에서는 두 번 연속 탭(더블 탭)으로 캐스팅하는 옵션을 설정에 둡니다.

### 4.3 입질 단계 (WAITING → BITE)

**신호 종류**

| 신호 | 소리 | 의미 | 탭하면? |
| --- | --- | --- | --- |
| 접근 신호 | `뽀글…` | 물고기가 다가옴 | 헛챔질 (실패) |
| 예비 입질 | `톡… 톡…` | 미끼를 건드림 | 헛챔질 (실패) |
| 가짜 신호 | 개구리, 나뭇잎, 바람 | 환경음 (함정) | 헛챔질 (실패) |
| **결정적 입질** | **`촤박!`** | **챔질 타이밍** | **성공 → 릴링** |

**판정**

- 결정적 입질 발생 후 **0~1.2초** 내 탭 → 챔질 성공
  - 0~0.4초: **퍼펙트 챔질** → 릴링 시작 시 거리 −10% 보너스
  - 0.4~1.2초: 일반 챔질
- 결정적 입질 이전 탭 → `FAIL_EARLY` (미끼 뺏김 / 물고기 도망)
- 1.2초 이후까지 무입력 → `FAIL_LATE` (놓침)

**대기 시간 설계**

- 착수 후 결정적 입질까지 **4~12초** (어종별 범위 내 랜덤)
- 그 사이 예비 신호를 **1~4회** 배치하여 청각 집중을 유지
- 결정적 입질 직전 0.5~1.5초는 **정적 구간**을 두어 긴장감을 극대화 (어종에 따라 생략하여 패턴을 다르게)

### 4.4 릴링 단계 (REELING)

**내부 변수**

| 변수 | 범위 | 설명 |
| --- | --- | --- |
| `distance` | 100 → 0 | 물고기까지의 남은 거리. 0이 되면 포획 |
| `tension` | 0 ~ 100 | 낚싯줄 장력. 100 도달 시 줄 끊김 |
| `slack_time` | 초 | 장력이 낮은 상태로 유지된 시간 |

**규칙**

- **누르는 중**: `distance` 감소, `tension` 상승 (어종별 상승 속도)
- **뗀 상태**: `tension` 하강, `distance`는 물고기 저항만큼 조금씩 증가
- `tension` ≥ 100 → `FAIL_SNAP` (줄 끊김)
- `tension` ≤ 10 상태가 3초 이상 지속 → `FAIL_ESCAPE` (바늘 빠짐)
- 물고기는 불규칙하게 **돌진(Run)** 을 일으켜 일시적으로 장력 상승 속도를 높입니다. 돌진 시작 시 `첨벙!` 소리로 예고합니다.

**장력 구간과 소리**

| 장력 | 구간 | 소리 | 진동 | 권장 행동 |
| --- | --- | --- | --- | --- |
| 0~10 | 느슨함 | 줄이 처지는 약한 소리 | 없음 | 눌러라 |
| 10~60 | 안전 | `드르륵… 드르륵…` | 없음 | 계속 눌러라 |
| 60~85 | 주의 | 마찰음 시작, 음높이 점진 상승 | 약한 진동 | 곧 떼라 |
| 85~100 | 위험 | `끼이익────!` 고음 | 강한 연속 진동 | 즉시 떼라 |

> **핵심 사운드 규칙**: 마찰음의 음높이(pitch)는 `tension`에 **연속적으로** 비례하여 상승합니다. 단계별로 뚝뚝 끊기는 소리가 아니라 매끄러운 상승이어야 플레이어가 위험도를 직관적으로 학습할 수 있습니다.

**릴링 성공 단위**

- 한 번 누르기~떼기를 1회 "당김"으로 보고, 어종별 **3~5회** 적절한 당김으로 포획되도록 거리·속도를 튜닝합니다.
- 남은 거리는 **릴 소리의 음량·근접감**으로 전달합니다 (물고기가 가까워질수록 물튀김 소리가 크고 선명해짐).

### 4.5 결과 단계 (CAUGHT / FAIL)

**포획 시**

- 큰 물튀김 + 짧은 성공 효과음
- 음성 안내: `"[어종], [크기]센티미터."`
- 개인 최대 기록 갱신 시: `"신기록입니다."` 추가
- 첫 포획 어종: `"새로운 물고기입니다."` 추가

> 예: "잉어, 48센티미터. 신기록입니다."

**실패 시**

| 실패 유형 | 소리 | 음성 안내 (선택) |
| --- | --- | --- |
| `FAIL_EARLY` | 물고기 도망치는 첨벙 | "너무 빨랐어요." |
| `FAIL_LATE` | 조용히 멀어지는 물소리 | "놓쳤어요." |
| `FAIL_SNAP` | `팅!` 줄 끊어지는 소리 | "줄이 끊어졌어요." |
| `FAIL_ESCAPE` | 바늘 빠지는 소리 | "물고기가 빠져나갔어요." |

실패 음성은 학습용 힌트입니다. 설정에서 끌 수 있습니다.

## 5. 어종 설계

MVP에서는 **5종**만 구현합니다. 어종마다 입질 패턴과 저항 특성이 달라, 숙련자는 소리만으로 어종을 추측할 수 있습니다.

### 5.1 어종 목록

| 어종 | 등급 | 출현 확률 | 크기(cm) | 특징 |
| --- | --- | --- | --- | --- |
| 붕어 | 흔함 | 45% | 10~35 | 느린 입질, 약한 장력. 입문용 |
| 잉어 | 보통 | 25% | 30~80 | 강한 저항, 긴 릴링 구간 |
| 배스 | 보통 | 22% | 20~60 | 갑작스러운 입질, 빠른 장력 변화 |
| 메기 | 희귀 | 7.5% | 40~110 | 무겁고 느린 저항, 긴 포획 시간 |
| 황금 잉어 | 전설 | 0.5% | 50~90 | 극히 낮은 확률, 독특한 입질 패턴 |

### 5.2 어종별 파라미터 (초기 튜닝값)

| 파라미터 | 붕어 | 잉어 | 배스 | 메기 | 황금 잉어 |
| --- | --- | --- | --- | --- | --- |
| 입질 대기(초) | 6~12 | 5~10 | 4~8 | 7~12 | 5~10 |
| 예비 신호 횟수 | 2~4 | 1~3 | 0~1 | 2~3 | 3 (고정 리듬) |
| 직전 정적 구간 | 있음 | 있음 | 없음 | 김 | 있음 |
| 챔질 판정창(초) | 1.4 | 1.2 | 0.9 | 1.2 | 1.0 |
| 장력 상승 속도 | 낮음 | 중간 | 높음 | 중간 | 높음 |
| 장력 하강 속도 | 빠름 | 중간 | 빠름 | 느림 | 중간 |
| 돌진 빈도 | 거의 없음 | 중간 | 잦음 | 드묾(길게) | 잦음 |
| 목표 당김 횟수 | 3 | 4 | 4 | 5 | 5 |

### 5.3 어종별 청각 시그니처

| 어종 | 입질 패턴 예시 | 릴링 감각 |
| --- | --- | --- |
| 붕어 | `뽀글… 톡…… 톡…… (정적) 촤박` | 가볍고 일정한 드르륵 |
| 잉어 | `뽀글… 톡… (정적) 촤박!` | 묵직하고 긴 드르륵 |
| 배스 | `(거의 예고 없이) 촤박!!` | 짧은 돌진이 잦아 장력이 출렁임 |
| 메기 | `뽀글…… 뽀글…… (긴 정적) 촥` (낮은 음) | 낮고 무거운 끌림, 느린 장력 회복 |
| 황금 잉어 | `톡 · 톡 · 톡` (일정한 3박 리듬) + 맑은 종소리 같은 물방울 → `촤박!` | 특유의 맑은 음색이 섞인 릴 소리 |

### 5.4 크기 결정

- 크기는 어종 범위 내에서 정규분포(평균 = 범위의 중앙 하단)로 결정합니다.
- 퍼펙트 챔질 시 크기 상위 구간 확률을 소폭 올려 실력 보상을 줍니다.

## 6. 사운드 디자인

이 게임에서 사운드는 배경음악이 아니라 **게임 인터페이스 그 자체**입니다.

### 6.1 소리–의미–행동 매핑

| 소리 | 의미 | 플레이어의 행동 |
| --- | --- | --- |
| 잔잔한 물소리 | 대기 | 기다리기 |
| 작은 물방울 소리 | 물고기 접근 | 집중하기 |
| 강한 물튀김 | 챔질 타이밍 | 터치 |
| 릴 돌아가는 소리 | 정상 릴링 | 계속 누르기 |
| 날카로운 줄 마찰음 | 장력 위험 | 손 떼기 |
| 줄 끊어지는 소리 | 실패 | 다시 시작 |
| 큰 물튀김 + 짧은 효과음 | 포획 성공 | 결과 듣기 |

MVP에서는 OS 기본 TTS로 시작하고, 정식 버전에서 성우 녹음으로 교체합니다.

### 6.3 사운드 설계 원칙

1. **신호음 간 혼동 금지** — 예비 입질과 결정적 입질은 음량·음색·길이가 명확히 달라야 합니다. 결정적 입질은 다른 모든 소리보다 크고 짧고 선명합니다.
2. **연속적 피드백** — 장력은 이산 단계가 아닌 연속 피치로 표현합니다. (권장: 장력 60→100 구간에서 피치 1.0→2.0배)
3. **덕킹(Ducking)** — 결정적 입질·위험 마찰음이 날 때 배경음을 자동으로 낮춥니다.
4. **공간감** — 스테레오 패닝으로 물고기의 좌우 움직임을 표현합니다. 이어폰 사용 시 몰입감을 크게 높입니다. 단, 패닝은 판정에 필수 정보가 되지 않도록 합니다 (모노 환경 대응).
5. **반복 피로 방지** — 원샷 효과음은 2~3개 변주 또는 피치/볼륨 랜덤을 적용합니다.

### 6.4 진동 (햅틱) — 보조 피드백

| 상황 | 패턴 |
| --- | --- |
| 결정적 입질 | 짧고 강한 1회 (40ms) |
| 챔질 성공 | 짧은 2회 |
| 장력 주의 (60~85) | 약한 주기적 펄스 |
| 장력 위험 (85~100) | 강한 연속 진동 |
| 포획 성공 | 길고 부드러운 1회 |

진동은 소리를 대체하지 않고 **보강**합니다. 설정에서 끌 수 있습니다.

## 7. 수집과 성장

### 7.1 원칙

- 상점, 인벤토리, 장비 강화는 **초기에 만들지 않습니다.**
- 성장은 오직 **플레이어의 청각 실력**입니다.
- 포획한 물고기와 개인 기록만 내부 저장합니다.

### 7.2 기록 항목

| 항목 | 내용 |
| --- | --- |
| 어종별 포획 횟수 | 붕어 23마리 등 |
| 어종별 최대 크기 | 신기록 판정 기준 |
| 총 포획 수 / 총 시도 수 | 성공률 산출 |
| 퍼펙트 챔질 횟수 | 실력 지표 |
| 도감 달성 | 5종 중 몇 종 발견 |

### 7.3 기록 듣기

- 화면을 **세 번 연속 탭**하면 음성으로 요약을 들려줍니다.
  > "지금까지 41마리를 잡았습니다. 다섯 종 중 네 종을 발견했습니다. 최대 기록은 메기 97센티미터입니다."
- 화면에는 검은 바탕 위에 최소한의 텍스트 기록 화면을 선택적으로 제공합니다 (보고 싶은 사람만).

## 8. 온보딩 (튜토리얼)

첫 실행 시 약 60초짜리 **음성 가이드 튜토리얼**을 진행합니다. 화면 설명은 없습니다.

1. "이어폰을 끼고 눈을 감아보세요." (3초 대기)
2. "화면 아무 곳이나 한 번 터치하면 낚싯줄을 던집니다." → 캐스팅 연습
3. "작은 소리는 아직이에요. 크게 물이 튀는 소리가 나면 바로 터치하세요." → 예비 신호와 결정적 입질을 한 번씩 들려준 뒤 챔질 연습 (붕어 고정, 판정창 2초)
4. "손가락을 누르고 있으면 릴을 감습니다. 날카로운 소리가 나면 손을 떼세요." → 마찰음을 낮은 피치→높은 피치로 미리 들려줌 → 릴링 연습 (장력 상승 50% 감속)
5. 첫 포획 → "붕어, 21센티미터. 첫 물고기입니다."

튜토리얼은 설정에서 다시 들을 수 있습니다.

## 11. MVP 개발 범위

| 항목 | MVP 사양 |
| --- | --- |
| 화면 | 검은색 단일 화면 |
| 입력 | 탭, 길게 누르기, 떼기 |
| 맵 | 낚시터 1곳 |
| 어종 | 5종 |
| 사운드 | 약 12~20개 (+ TTS 음성) |
| 게임 상태 | 캐스팅, 대기, 챔질, 릴링, 결과 |
| 데이터 | 포획 횟수, 어종, 최대 크기 |
| 네트워크 | 필요 없음 |
| 계정·로그인 | 없음 |
| 그래픽 에셋 | 없음 |

### 11.1 기술 스택

- 게임 엔진 불필요. **iOS: Swift (AVAudioEngine)**, **Android: Kotlin (Oboe 또는 SoundPool + AudioTrack)** 으로 충분한 규모입니다.
- 핵심 기술 요구사항:
  - **저지연 오디오**: 입력→소리 반응 50ms 이하 목표. 챔질 판정은 오디오 재생 시각 기준으로 계산합니다.
  - **실시간 피치 조절**: 줄 마찰음 루프의 피치를 프레임 단위로 변경
  - **백그라운드/화면 꺼짐 대응**: 화면이 꺼지면 게임 일시정지
- 대안: 빠른 프로토타입을 위해 웹(Web Audio API) 버전으로 먼저 로직을 검증하는 것도 가능합니다.

### 11.2 개발 단계

| 단계 | 기간(예상) | 산출물 |
| --- | --- | --- |
| P0. 로직 프로토타입 | 1주 | 임시 효과음으로 전체 루프 동작, 파라미터 실시간 조절 디버그 패널 |
| P1. 튜닝 | 1~2주 | 챔질 판정창, 장력 속도, 포획 성공률 조정 (사내 블라인드 테스트) |
| P2. 사운드 제작 | 2주 | 정식 효과음 18종, 음성 안내 |
| P3. 온보딩·설정·저장 | 1주 | 튜토리얼, 설정, 로컬 기록 |
| P4. 외부 테스트 | 1~2주 | 클로즈드 베타, 지표 수집 후 재튜닝 |

> 사운드가 완성되기 전에도 게임 로직을 검증할 수 있습니다. 임시 효과음으로 **입질의 반응 시간, 장력 변화 속도, 포획 성공률**부터 튜닝합니다.

## 13. 핵심 리스크와 대응

### 13.1 가장 큰 위험: 지루함

> 핵심 위험은 단순한 게임이 아니라 **지루한 게임**이 되는 것입니다.

아무것도 보이지 않는 상태에서 30초씩 입질을 기다리게 하면 플레이어는 이탈합니다.

**대응**

- 입질 대기 시간을 **4~12초**로 짧게 유지
- 작은 입질과 **가짜 신호**로 대기 중에도 계속 청각적 판단을 요구
- 어종마다 입질 리듬을 달리해 "이번엔 뭘까?" 하는 추측의 재미 부여
- 결과 후 즉시 재캐스팅 가능 (대기 없는 루프)

### 13.2 기타 리스크

| 리스크 | 대응 |
| --- | --- |
| 실패 원인을 모름 (보이지 않으니까) | 실패 유형별 고유 소리 + 음성 힌트 |
| 기기별 오디오 지연 차이 | 설정에 오디오 지연 보정(캘리브레이션) 옵션 추가 검토 |
| 시끄러운 환경에서 신호 못 들음 | 이어폰 권장 안내, 진동 보조, 덕킹 처리 |
| 주머니·침대 오입력 | 더블 탭 캐스팅 옵션, 화면 꺼짐 시 일시정지 |
| 콘텐츠 소진 (5종) | 업데이트 로드맵에 신규 낚시터·어종 준비 |
| 스토어 노출 (스크린샷이 검은 화면) | 사운드 파형·일러스트 기반 마케팅 이미지, 영상은 "눈 감고 플레이" 콘셉트 강조 |

## 15. 요약

《눈 감고 낚시》는 **검은 화면, 두 가지 조작, 소리 하나**로 완성되는 게임입니다.

- 소리를 정확히 듣는 것이 곧 실력이고,
- 어종마다 다른 소리 패턴이 학습과 수집의 재미가 되며,
- 화면을 보지 않아도 되기에 누워서, 걸음을 멈추고, 눈을 감고 어디서든 몰입할 수 있습니다.

MVP는 엔진 없이 네이티브로 4~8주 안에 검증 가능한 규모이며, 가장 먼저 **"기다림이 지루하지 않은가"** 와 **"소리만으로 장력을 판단할 수 있는가"** 두 가지를 검증해야 합니다.
